# Sport Drive

Локальна система прокату спортивного спорядження: WPF, .NET Framework 4.7.2, Entity Framework 6 та SQLite. Розрахунки демонстраційні: програма веде журнал, а не переказує гроші.

## Запуск готового комплекту

Потрібні Windows x64 і .NET Framework 4.7.2 або сумісна новіша версія .NET Framework.

1. Повністю розпакуйте `SportDrive-win-x64.zip` у папку з правом запису.
2. Запустіть `SportRentApp.exe`. Залиште поруч усі DLL, конфігурацію, базу та папку `CatalogImages` з архіву.
3. Створіть першого менеджера через початкову форму. Стандартного логіна й пароля немає.
4. Увійдіть менеджером, створіть працівників та кіоск. Для працівника виберіть робоче місце «Каса» або «Склад» і почніть зміну.

Клієнт входить на кіоску за номером телефону, вибирає спорядження й дати та отримує номер заявки. Каса оформлює оплату і передає замовлення на склад. Склад підтверджує готовність, після чого каса видає спорядження та приймає повернення. Пошкодження і штрафи перевіряє менеджер.

Перший запуск чистого комплекту пропонує створити менеджера. У комплекті є десять демонстраційних товарів із фотографіями; акаунти, оренди, платежі та повідомлення створюються під час роботи.

## Збірка з вихідного коду

Для збірки потрібні Windows, Visual Studio з компонентом .NET desktop development і targeting pack .NET Framework 4.7.2. Відсутні NuGet-пакети відновлює скрипт збірки; для цього потрібен доступ до мережі.

```powershell
.\scripts\Build.ps1
.\scripts\Check-Coursework.ps1
.\scripts\Package.ps1
```

`Check-Coursework.ps1` перевіряє сценарії на окремій тестовій базі в `artifacts`. `Package.ps1` створює нову папку `artifacts/release-*` із готовим комплектом Windows x64 та окремим архівом вихідного коду.

## Публікація

Вміст `SportRentApp-source.zip` призначений для репозиторію. Готовий `SportDrive-win-x64.zip` призначений для вкладення до GitHub Release. В архів вихідного коду входить лише чиста демонстраційна БД. Робочі бази, `bin`, `obj`, `.vs`, локальні пакети й результати перевірок не потрібно додавати до репозиторію.

## Робочі дані

`RentalShop.db` зберігається поруч із виконуваним файлом. Збірка додає демонстраційну БД лише за відсутності робочої. Перед оновленням старої схеми програма створює резервну копію. Перед ручним резервним копіюванням закрийте всі екземпляри програми та збережіть базу разом із `CatalogImages` і `ProfileImages`, якщо вони є. Під час оновлення не замінюйте робочу базу чистою базою з архіву.

Це локальний навчальний прототип: одна позиція в замовленні, ідентифікація клієнта за телефоном без SMS, фінансові записи без реальних переказів.
